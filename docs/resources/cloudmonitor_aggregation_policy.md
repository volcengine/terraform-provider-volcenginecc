# volcenginecc_cloudmonitor_aggregation_policy (Resource)

CloudMonitor alert aggregation strategy.

## Example Usage

```terraform
resource "volcenginecc_cloudmonitor_aggregation_policy" "primary_cloudmonitor_aggregationpolicy_full" {
  aggregations = [{
    group_by       = ["rule_id", "region"]
    group_interval = 60
    group_wait     = 30
    level          = "all"
    repeat_downgrade = {
      enable              = true
      max_repeat_interval = 3600
      mode                = "doubled"
    }
    repeat_interval = 120
  }]
  description = "完整all兜底及官方示例降频配置"
  is_default  = false
  name        = "ccapi-agp-9011199b-full"
}
```

### Nested Schema for `aggregations`

Optional:

- `group_by` (Set of String) Alert group fields, default [rule_id+region]. Currently only supports: 1. rule_id+region grouping, i.e., default grouping by severity. 2. Any rule_id+region+* grouping, i.e., each faulty resource forms a separate group, notification cycle is not affected by other faulty resources; in this mode, GroupWait/GroupInterval are not effective, default is 0. 3. rule_id+region+keys grouping based on actual alert group fields, grouped by key match and value. For example, rule_id+region+namespace+cluster+pod, each namespace+cluster+pod combination forms a separate group, notification cycle is not affected by other faulty resources; this method requires configuring a fallback aggregation strategy.
- `group_interval` (Number) Alert group wait interval for the 2nd to Nth times, in seconds, range is 5 seconds to 24 hours. If there is a new alert or recovery in the alert group, send immediately after GroupInterval and recalculate RepeatInterval.
- `group_wait` (Number) Alert group initial wait time, in seconds, range is 5 seconds to 24 hours. If not specified, defaults to GroupInterval.
- `level` (String) Alert severity, supports p0/p1/p2/all. all indicates the fallback aggregation strategy, meaning alerts are aggregated without distinguishing severity, but messages are still sent separately by severity. If not all p0/p1/p2 levels are configured, the "all" fallback strategy must be configured.
- `repeat_downgrade` (Attributes) Notification frequency reduction configuration. Note: P0 does not support notification frequency reduction, while P1/P2 do. (see [below for nested schema](#nestedatt--aggregations--repeat_downgrade))
- `repeat_interval` (Number) Alert repeat notification interval, in seconds, range is 1 minute to 24 hours.
